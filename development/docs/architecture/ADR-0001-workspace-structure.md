# ADR-0001 — 제품 워크스페이스 구조

- 상태: Accepted
- 일자: 2026-07-31

## 배경

프로젝트가 리서치로 시작해 원자료, 분석 스크립트와 보고서가 루트에 혼재했다. 향후 제품
기획, 디자인, 클라이언트, 서버와 배포 설정이 추가되면 파일 위치뿐 아니라 정본과 의존
방향이 불명확해질 위험이 있었다.

## 결정

루트는 다음 두 책임 경계로 나눈다.

- `coursework`: 미션, 케이스 스터디와 포트폴리오
- `development`: 선택적으로 구현할 앱·서비스·공용 코드·인프라·기술 결정

`coursework/case-study` 안에서 리서치, 제품 정의와 디자인을 구분하고,
`coursework/missions`는 제출 상태를 관리한다.

의존 방향은 원칙적으로 `research → product → design → implementation`이다. 뒤 단계에서
발견한 사실은 앞 단계의 정본을 갱신하며, 같은 내용을 복제하지 않는다.

## 결과

- 리서치 파이프라인은 `coursework/case-study/research` 안에서 독립적으로 실행 가능하다.
- 제품과 기술 스택이 정해지기 전에도 문서와 코드의 자리가 명확하다.
- 앱과 서비스를 섣불리 생성하지 않아 초기 과설계를 피한다.
- 새 실행 단위가 생기면 루트 검증 명령에 해당 테스트를 연결해야 한다.
