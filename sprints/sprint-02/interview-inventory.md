# 소모임 — 가설 인벤토리

페르소나 '최보람'의 추정 항목을 검증 가능한 가설로 정리한 문서. 진행 스크립트는 별도 문서(**소모임_[인터뷰지.md](http://인터뷰지.md)**)에 있고, 코드는 두 문서가 공유한다.

---

## 0. 이 문서 쓰는 법

### 가설은 두 종류다


| 종류                        | 묻는 것                         | 코딩                                      |
| ------------------------- | ---------------------------- | --------------------------------------- |
| **사실형** (A·B·C·D·E·H·I·R) | 이런 일이 실제로 일어나는가              | **2값** — 지지 / 기각 / 판단불가                 |
| **속성형** (S)               | 이 정보가 판단에 쓰이는가, 쓰인다면 어느 방향인가 | **4값** — 미사용(N) / 방향(a·b·c·d) / 판단불가(U) |


속성형을 2값으로 코딩하면 "기각"이 두 가지 뜻을 갖는다. "성비가 제외 조건이다 → 기각"은 *성비를 안 본다*는 뜻일 수도, *보긴 보는데 이성이 많은 쪽을 선호한다*는 뜻일 수도 있다. 처방이 정반대인데 라벨이 같아진다. 그래서 3장에서 분리했다.

### Tier — 쳐내는 기준

각 가설마다 **"답이 참일 때와 거짓일 때 만들 게 달라지는가?"**로 판정한다.


| Tier   | 기준                           | 처리                   |
| ------ | ---------------------------- | -------------------- |
| **T1** | 핵심 기능·정보 구조가 갈린다             | 반드시 검증. 인터뷰 시간의 70%  |
| **T2** | 우선순위·기본값·카피만 바뀐다             | 여유 있으면. 관찰로 대체 가능    |
| **T3** | 답이 뭐든 같다 / 이미 안다 / 인터뷰로 못 안다 | **묻지 않는다.** 미검증으로 명시 |


T3도 문서에 남긴다. "왜 안 물었는지"를 쓰는 것 자체가 설계 근거다.

### 코드 표기

- `[취미]` / `[관계]` — 어느 관점에서 나온 가설인지
- `↔` — 배타 관계. 둘 중 하나만 참일 수 있다
- ★ — 결정적 테스트

> E1~E5, F1~F4, G1~G4는 속성형이므로 **S1~S12로 이관**했다. 코드 연속성을 위해 번호는 재사용하지 않는다.

## 1. 핵심 갈림길 — 취미 목적인가 관계 목적인가

다른 모든 가설의 해석이 여기에 걸려 있다. **먼저 판정하고 나머지를 읽는다.**

- **취미 목적**: 활동 자체가 목적. 사람은 활동을 성립시키는 조건
- **관계 목적**: 활동은 낯선 사람과 반복해서 같은 공간에 있기 위한 **사회적으로 안전한 명분**. 사려는 건 "억지로 노력하지 않아도 알고 지내게 되는 사람들"

### 판정 방법 — 직접 물으면 안 된다

"사람 만나려고 오셨어요?"는 100% 부정당한다. 관계 목적을 인정하는 데는 사회적 부담이 따르고, "취미 하려고요"가 훨씬 말하기 쉽다. 자기 자신에게도 인정하지 않는 경우가 많다. 아래 3개의 교차 확인으로만 판정한다.

**★ 결정적 테스트 3개**


| #   | 질문                                            | 관계 목적 시그널            |
| --- | --------------------------------------------- | -------------------- |
| 1   | 가려던 모임이 마감이었으면 다른 활동을 찾으셨을까요, 다음 회차를 기다리셨을까요? | 다른 활동으로 갈아탐 = 활동은 수단 |
| 2   | 그 모임 사람들이 전부 새로운 분들로 바뀐다면 계속 나가셨을까요?          | 망설임·부정 (망설인 시간을 기록)  |
| 3   | 그만둔 모임, 활동 자체는 어땠어요?                          | "활동은 괜찮았는데…"         |


**보조 지표**: 회상 질문에서 사람 얘기와 활동 얘기 중 무엇이 먼저 나오는지, 비율은 어떤지 정량 기록.

**보고서 기재 필수**: 이 가설군은 자기보고 편향(social desirability bias)에 취약하며 간접 지표 교차 확인으로만 판단했음을 한계로 명시.

### 관점별 결론 대조

이 표가 **"근거가 구체적이어야 기능 정의가 안 흔들린다"의 실체다.** 정하지 않고 기능을 뽑으면 두 열이 섞인 물건이 나온다.


| 영역      | 취미 목적일 때          | 관계 목적일 때                     |
| ------- | ----------------- | ---------------------------- |
| 유저군     | 취미활동 하고 싶은 사람     | 관계를 조달하려는 사람 (별도 축)          |
| IA 최상단  | 카테고리(취미 종류)       | 참여자 구성 + 상호작용 구조             |
| 핵심 정보   | 활동 내용·난이도·일정      | 재참석률·신입 유입·연령대·성비            |
| Must 기능 | 취미/가격 필터, 활동 상세   | 참석 로그 공개, 신입 진입 지원, 모임 성격 명시 |
| 성공 지표   | 가입 전환             | 3회차 잔존율                      |
| 경쟁자     | 당근·문토·프립          | 회사 동료·기존 친구·러닝크루             |
| 카피      | "원하는 취미 모임을 찾으세요" | "혼자 가도 어색하지 않은 모임"           |

### C. 플랫폼 선택 — 당근 3갈래 ★핵심 축

> "당근 왜 안 쓰세요?"라고 물으면 그 자리에서 이유를 지어낸다(confabulation). **인지 → 고려 → 이탈 순서로 분해**해서, 앞 단계가 부정이면 뒤를 묻지 않는다.


| 코드      | 가설                                                 | Tier | 처방이 달라지는 지점                        |
| ------- | -------------------------------------------------- | ---- | ---------------------------------- |
| **C1**  | 당근에 모임 기능이 있다는 걸 **모른다** (인지 실패)                   | T1   | 참이면 제품이 아니라 노출 문제 → **기능 근거로 못 씀** |
| **C2**  | 알지만 '당근=중고거래' 연상 때문에 떠오르지 않는다 (고려 실패)              | T1   | 포지셔닝 문제 → "모임 찾겠다고 마음먹었을 때 여는 앱"   |
| **C3**  | 들어갔지만 판단이 안 돼서 나왔다 (이탈)                            | T1   | UX·정보 문제 → **그때 부족했던 정보가 곧 만들 것**  |
| **C6**  | 비교한 적 없고 검색 결과·노출로 소모임에 왔다                         | T1   | 참이면 "왜 소모임인가"에 **답이 없다.** 그 자체가 발견 |
| C5      | 당근 모임은 일회성이라 정기성 니즈를 못 채운다                         | T1   | 참이면 정기성이 포지셔닝 축                    |
| C4      | 당근은 동네 기반이라 범위가 좁다                                 | T2   |                                    |
| C7      | 인스타·오픈카톡·네이버 카페가 실질 경쟁자다                           | T2   |                                    |
| **R32** | 관계 목적이면 경쟁자는 앱이 아니라 **회사 동료·기존 친구·운동 모임**이다 `[관계]` | T1   | 참이면 경쟁 분석의 축 자체가 바뀜                |
| R34     | 오픈카톡·디스코드는 오프라인 전환이 안 돼 실패했다 `[관계]`                | T1   | 들어가 본 적 / 실제로 만난 적                 |
| R33     | 운동(러닝크루·클라이밍)이 이미 그 역할을 한다 `[관계]`                  | T2   |                                    |


**진행 순서**: C6 → C2 → C1 → (인지했으면) C3. C1이 부정이면 C2·C3는 묻지 않는다.

## 3. 속성형 가설 S1~S12 (4값 코딩)

### 3층으로 분리한다


| 층            | 묻는 것                   | 측정                               |
| ------------ | ---------------------- | -------------------------------- |
| **L1 관련성**   | 애초에 판단에 쓰이는가           | **자발 언급 여부와 순서** (인터뷰지 §5 1~2단계) |
| **L2 방향**    | 쓰인다면 어느 값을 선호하는가       | 양방향 질문 (§5 3단계)                  |
| **L3 강도·임계** | 제외 조건인가 가점인가, 경계는 어디인가 | 카드 소트 (§5 4단계)                   |


**앵커에 따라 얻을 수 있는 층이 다르다.** 실제 참석 경험자(앵커 A)만 L3까지 나오고, 참석 경험 없이 화면만 본 참가자(앵커 C)는 L1·L2까지다. 특히 S8(회비)·S9(이동시간)의 임계값은 실제 지불·이동에서만 나오므로, 앵커 C에서는 `U`로 두고 카드 소트로만 확인한다. **가정형으로 채우지 않는다.** 집계 시 앵커별로 분리한다 — 실제로 3만원을 내본 사람의 "3만원"과 화면에서 숫자만 본 사람의 "3만원"은 다른 데이터다.

**L1이 부정이면 L2·L3를 묻지 않는다.** 판단 기준이 아닌 항목에 방향을 물으면 그 자리에서 의견이 만들어진다.

**코딩 값**: `N` 미사용 / `a·b·c·d` 방향 / `U` 판단불가 `N`이 여러 명에게서 나오면 실패가 아니라 **강한 발견**이다. 페르소나에서 항목을 빼고 정보 설계에서 그만큼 지면을 비운다는 뜻이다.

**사전 예측 열은 인터뷰 전에 채운다.** 빗나간 항목이 보고서에서 가장 값진 부분이 된다.

### S1. 최근 활동 게시글 `(구 E1, R36)`

- **L2**: (a) 최근 글이 있어야 함 / (b) 빈도보다 내용 / (c) 안 봄
- **L3**: 며칠까지 허용하는가. 없으면 제외인가 감점인가
- **분기**: 최신성을 보는 목적이 **활동 지속 확인**인지 **사람이 계속 오는지 확인**인지 → 후자면 노출해야 할 건 게시글이 아니라 **참석 로그**
- **사전 예측**: (a)

### S2. 참석자 반복률 `(구 E2, R11, R22, R23)`

- **L2**: (a) 높을수록 좋음(관계 형성 가능) / (b) 높으면 부담(이미 굳은 그룹) / (c) 적정선 있음 / (d) 안 봄
- **L3**: (b)라면 어느 수준부터 부담인가
- **주의**: 구 E2와 R11이 **같은 속성의 정반대 방향**이었다. 방향을 미리 정하지 말 것
- **사전 예측**: (c)

### S3. 연령대 `(구 E3, F2, R15)`

- **L2**: (a) 비슷할수록 좋음 / (b) 다양한 게 좋음 / (c) 특정 대역만 아니면 됨 / (d) 안 봄
- **L3**: (c)라면 제외 대역은 어디인가 — 페르소나는 "40대 이상 비율"로 단정했으나 근거 없음
- **분기**: 진짜 축이 **연령 숫자**인지 **생애 단계**(직장 연차·결혼 여부)인지 → 후자면 필터 축이 달라짐
- **사전 예측**: (a) + 생애 단계 축

### S4. 성비 `(구 E4, F1, R16)`

- **L2**: (a) 동성 비율 높은 쪽 / (b) 균형 / (c) 신경 안 씀 / (d) 이성 비율 높은 쪽
- **L3**: (a)라면 이유가 **편안함**인지 **이성 접근 회피**인지 → 후자면 해법은 성비가 아니라 '모임 성격 명시'
- **주의**: 가장 민감. 절대 먼저 꺼내지 말 것
- **사전 예측**: (a), 이유는 접근 회피

### S5. 뒤풀이 `(구 E5, R9)`

- **L2**: (a) 없는 편이 좋음 / (b) 있는 편이 좋음 / (c) 있되 선택 가능해야 함 / (d) 안 봄
- **L3**: (a)라면 원인이 술 / 종료 시각 불확실 / 이성 분위기 / 빠지기 어려움 중 무엇인가
- **주의**: **관계 목적이 참이면 (b)·(c)가 나올 수 있다.** 뒤풀이가 관계 형성의 실질 장소일 가능성. 페르소나의 '비선호' 단정이 가장 위태로운 항목
- **사전 예측**: (c)

### S6. 인원 규모 `(구 F4, R17)`

- **L2**: (a) 소규모 / (b) 대규모 / (c) 적정 구간 / (d) 안 봄
- **L3**: 구간의 상·하한. **정원인지 실참 인원인지** 구분
- **사전 예측**: (c), 4~8명

### S7. 참가자 실력대 `(구 F3, R8)`

- **L2**: (a) 나와 비슷 / (b) 나보다 잘하는 쪽 / (c) 초보 위주면 제외 / (d) 안 봄
- **주의**: 관계 목적이면 (d)가 나온다. A2/A3 판정의 보조 지표
- **사전 예측**: (a)

### S8. 회비 `(구 G1, R38)`

- **L2**: (a) 낮을수록 좋음 / (b) 일정 수준 이상이어야 신뢰 / (c) 금액보다 용처 / (d) 안 봄
- **L3**: 첫 참석과 지속 참석의 허용 금액이 다른가 → 다르면 '관계 리스크 비용' 지지
- **주의**: 가정형 상한 질문 금지, **과거 실지출로만**. 무료가 오히려 불신 신호일 가능성 — 스프린트1의 무료 모임 논지와 충돌할 수 있는 지점이므로 반드시 열어둘 것
- **사전 예측**: (a), 첫 회 임계 별도

### S9. 위치·이동 시간 `(구 G4)`

- **L2**: (a) 가까울수록 / (b) 특정 지역 / (c) 시간만 맞으면 무관
- **L3**: 허용 편도 시간 — 과거 실제 이동 시간으로
- **사전 예측**: (a), 30~40분

### S10. 시작·종료 시간 `(구 G2, G3)`

- **L2**: (a) 종료 시각 명시 필수 / (b) 시작 시각만 / (c) 요일이 더 중요
- **L3**: 종료 시각 미명시가 제외 조건인가 → 참이면 **가격보다 총 소요 시간이 제약**
- **사전 예측**: (a)

### S11. 호스트 `(구 F5, R25, R26)`

- **L2**: (a) 활동 실력·경력 / (b) 운영·중재 스타일 / (c) 성별·연령 / (d) 안 봄
- **L3**: (b)라면 기대 행동이 진행인지 챙김인지 방임인지
- **분기**: (a)면 취미 관점, (b)면 관계 관점 지지
- **사전 예측**: (b)

### S12. 회원 수·활성도 `(구 R11 파생)`

- **L2**: (a) 많을수록 좋음 / (b) 많으면 부담 / (c) 적정 구간 / (d) 안 봄
- **L3**: (b)라면 신규 유입 흔적으로 무엇을 보는가
- **주의**: 소모임의 기본 정렬 가정("회원 많음=좋음")이 여기서 깨질 수 있다
- **사전 예측**: (c)

## 5. 페르소나 미확정 대장

페르소나에 단정형으로 적혀 있지만 **방향조차 모르는** 항목들. 검증 전까지 이 상태 그대로 표기한다.


| 페르소나 기재           | 확인된 것 | 모르는 것                                          | 코드    |
| ----------------- | ----- | ---------------------------------------------- | ----- |
| 뒤풀이 비선호           | 없음    | ① 판단 기준인지 ② 싫다면 원인 축 ③ 오히려 관계 형성의 핵심일 가능성      | S5    |
| 비슷한 연령대 선호        | 없음    | ① 기준인지 ② 비슷한 게 좋은지 다양한 게 좋은지 ③ 축이 연령인지 생애 단계인지 | S3    |
| 동성 선호 / 이성 많으면 고민 | 없음    | ① 보긴 보는지 ② 방향 ③ 취향인지 접근 회피인지                   | S4    |
| 회당 3만원 이내         | 없음    | ① 실제 지출 이력 ② 첫 회와 지속 시 금액 차이 ③ 가격인지 리스크 비용인지   | S8    |
| 40대 이상 비율이 제외 조건  | 없음    | 임계값의 존재와 위치                                    | S3 L3 |
| 리드 경험 없어서 개설 안 함  | 없음    | 진짜 이유 (D1/D2/D3/D4)                            | D 블록  |
| 최근 활동 게시글 중시      | 없음    | 보는 목적이 활동 지속인지 사람 지속인지                         | S1    |
| 동일 회원 반복 참여 중시    | 없음    | 신뢰 신호인지 핵심 가치인지, 아니면 부담인지                      | S2    |


**처리 방법**: 지우지 말고 **"가설 — 미검증"** 태그를 달아 그대로 둔다. 인터뷰 후 항목별로 `확인됨 / 기각됨 / 방향 반대로 확인됨 / 판단 기준 아님`으로 갱신한다. 세 번째 라벨이 나오면 그게 보고서에서 가장 강한 부분이 된다.

## 6. 분석 규칙

- **A2/A3 판정은 ★ 3개의 교차 확인으로만.** 단일 문항으로 판정하지 않는다
- 관계 목적 가설군은 자기보고 편향에 취약 → 보고서에 한계 명시
- 발화는 해석하지 말고 원문으로 코딩한 뒤, 코딩 결과를 놓고 해석한다
- **자발 언급(§5 1~2단계)과 제시 후 응답(3~4단계)을 합산하지 않는다.** 별도 집계 후 대조
- L1이 `N`인 속성은 방향 집계에서 제외하고, `N`의 수를 따로 센다
- 7명 중 자발 언급 0명인 속성은 **상세 화면 하단 또는 비노출 후보**로 표시
- **실사용자 2명의 데이터는 사례로만 인용한다.** "사용자들은 ~한다"로 일반화하지 않는다
