# 소모임 — 인터뷰지

진행에 필요한 모든 것. 사전 설문부터 페르소나 작성 템플릿까지. 대괄호 안 코드는 검증 대상 가설(→ **소모임_[가설인벤토리.md](http://가설인벤토리.md)**)이며 **참가자에게 읽지 않는다.**

- 총 문항: **핵심 68 + 심화 71 = 139** (+ 사전 설문 22)
- `P1-3` = 페르소나 블록 1의 3번 / `[S3]` `[R20]` = 대응 가설
- ● 핵심(전원) / ○ 심화(시간·앵커 되는 사람만) / ▷ 프로브 / ★ 결정적 테스트

# 1. 세션 설계

## 1-1. 두 개의 셀

기존 인터뷰이 7명 중 소모임 실사용자는 2명. **두 셀은 서로 다른 질문에 답하므로 합쳐서 분석하지 않는다.**


|        | **셀 A — 미사용 5명**             | **셀 B — 실사용 2명**       |
| ------ | ---------------------------- | ---------------------- |
| 정체     | 멘토가 요구한 '초기 탐색자'             | 가입 이후 경험 보유자           |
| 답하는 것  | 첫 탐색 판단, 즉시 제외, 정보 공백, 비교 행동 | 이탈 시점과 이유, 관계 형성 여부    |
| 데이터 성격 | 관찰(행동)                       | 회상(진술)                 |
| 산출물    | 화면·정보 설계 근거                  | 성공 지표, 지속 설계 근거        |
| n      | **5 — 사용성 패턴 도출 가능**         | **2 — 패턴 아님. 사례로만 인용** |


미사용 5명은 결함이 아니라 기회다. 앱을 처음 보는 사람의 첫 판단은 **한 사람당 한 번밖에 관찰할 수 없다.**

## 1-2. 앵커 — 질문을 어디에 거는가

**회상형 질문은 회상할 경험이 없으면 없는 기억을 만들어낸다.** 참가자마다 먼저 판정한다.


| 앵커        | 조건             | 거는 대상            | 답할 수 있는 블록          |
| --------- | -------------- | ---------------- | ------------------- |
| **A 참석형** | 실제로 나가본 모임이 있다 | 그 모임             | 전부                  |
| **B 탐색형** | 알아만 봤다         | 알아보던 때           | P8·P9 제외            |
| **C 화면형** | 둘 다 없다         | **방금 과업에서 본 화면** | P7~P9 제외, 과업 회고로 대체 |


**판정**: 사전 설문 9번. 애매하면 오프닝에서 → "지금까지 실제로 나가보신 취미 모임이 있으세요? 알아만 보고 안 가신 것도 포함해서요."

- 앵커 C는 **과업을 하는 셀 A만 가능**하다. 과업 없이 속성 모듈을 하면 걸 데가 없다
- 셀 B는 항상 앵커 A
- **앵커 유형을 기록지에 반드시 적는다.** 실제로 돈을 내본 사람의 "3만원"과 화면에서 숫자만 본 사람의 "3만원"은 다른 데이터다. 집계 시 분리한다

## 1-3. 시간 배분 — 60분 × 2회

가설 검증만이면 35분이면 되지만, **페르소나까지 채우려면 안 맞는다.** 7명 전원 재접촉이 가능하므로 2회로 나눈다. 1회차 후 질문을 고칠 수 있는 것도 이점이다.


|     | 1회차 (60분) — 사람 이해                                                | 2회차 (60분) — 판단과 경험                                            |
| --- | ---------------------------------------------------------------- | ------------------------------------------------------------- |
| 구성  | P1 5 / P2 7 / P3 7 / P4 5 / P5 8 / P10 5 / P12 5 / P13 4 + 여유 14 | P7 6 / P8 7 / P9 6 / P11 4 / **과업 20** / **속성 모듈 12** / 마무리 5 |


- 앵커 C는 2회차에서 P8·P9가 빠지므로 **과업을 30분으로** 늘린다
- 셀 B는 과업을 10분으로 줄이고("지금 새로 하나 더 가입한다면") P8·P9에 시간을 쓴다

## 1-4. 진행 순서

1. **셀 A 중 가장 편한 한 명을 파일럿으로.** 끝나고 질문 수정 후 나머지 적용 (파일럿 데이터도 수정 이력과 함께 보존)
2. 셀 A 나머지 4명 → 셀 B 2명. 셀 A에서 나온 패턴을 셀 B 질문에 반영
3. 세션 간 최소 하루 간격. 직후 5분 기록(§8)을 거르면 3명째부터 기억이 섞인다

# 2. 준비와 진행 원칙

**체크리스트**

- [ ] 사전 설문 발송 (세션 전날) 및 응답 확인
- [ ] 앵커 유형 판정 (설문 9번)
- [ ] 녹음 동의 / 셀 A는 화면 녹화 별도 동의
- [ ] §8 기록지 준비
- [ ] §7 카드 12장 준비
- [ ] 참가자별 사용해본 모임 앱 목록 확인 — 노이즈가 아니라 **공변량**이다
- [ ] 이전 인터뷰 답변 미리 읽기 (같은 질문 반복하면 신뢰를 잃는다)
- [ ] 참가자에게 **알림 끄기** 안내 — 개인 알림이 녹화에 남으면 그 파일을 못 쓴다

**동의 문구 (그대로 읽기)**

> "오늘 내용은 제 학습 프로젝트 안에서만 쓰고, 이름이나 알아볼 수 있는 정보는 다 빼고 정리할게요. 녹음해도 괜찮으실까요? 답하기 불편한 질문은 넘어가셔도 됩니다."

**오프닝 (1회차)**

> "지난번 시간 내주셔서 감사했어요. 정리하다 보니 못 여쭤본 게 있어서 다시 연락드렸어요. 오늘은 제가 만드는 거 얘기는 안 하고, ○○님이 실제로 어떻게 하셨는지만 여쭤볼게요. **그리고 해당 없는 건 없다고 하셔도 됩니다.**"

**진행 원칙**

1. 말하는 시간 20%, 듣는 시간 80%
2. 추상적인 답 → 무조건 시점으로. "그게 마지막으로 언제였어요?"
3. 칭찬 → 흘려보낸다. "감사합니다, 그런데 지금은 어떻게 하고 계세요?"
4. 해석하지 말고 **원문 그대로** 적는다
5. 침묵을 채우지 않는다. 3초 기다린다

**금지**

- "이런 기능 있으면 쓰실 것 같아요?" — 가정형은 가정형 답을 받는다
- "사람 만나려고 가시는 거예요?" — 관계 목적은 직접 물으면 100% 부정당한다
- "얼마까지 내실 수 있어요?" — 가정형 금액은 답이 부정확하다. 사전 설문의 실지출로 대체
- **"지난번에 ○○라고 하셨죠?"** — 그 순간 답이 고정된다. 처음처럼 다시 묻고, 답이 달라지면 그 차이를 기록한다
- **우리 문제의식 재설명** — 한 번 들은 사람은 우리가 원하는 답을 안다. 맨 마지막 1분 전까지 금지
- 속성 이름(뒤풀이·나이·성비)을 우리가 먼저 발음하는 것 → §7 3단계 전까지

**재접촉 편향**: 응해줬다는 것 자체가 협조적이라는 뜻이고, 도우려고 없는 불편도 만들어낸다. 오프닝의 **"없으시면 없다고 하셔도 돼요"**를 반드시 넣을 것.

# 3. 사전 설문 (구글폼, 5분)

세션 전날 발송. **여기서 받은 답을 인터뷰에서 다시 묻지 않는다.** 이것만으로 인터뷰 15분이 빈다.

**기본**

1. 나이 / 2. 성별 / 3. 직업·직무 / 4. 연차 / 5. 거주 지역(구 단위)
2. 근무 형태 — 고정 출퇴근 / 유연근무 / 재택 병행 / 교대 / 프리랜서
3. 평일 퇴근 후 자유 시간 — 없음 / 1시간 이내 / 1~2시간 / 2~3시간 / 3시간 이상
4. 주말 중 모임에 쓸 수 있는 시간대 (복수)

**모임 이력** 9. **지금까지 취미 모임에 나가본 적** — 정기적으로 다녔다 / 몇 번 나가봤다 / 알아만 봤다 / 없다 ← **앵커 판정** 10. 나가봤다면 어떤 모임이었나요 (최근 3개, 자유 기술) 11. 각 모임을 알게 된 경로 — 친구·지인 / 학교·회사 / 앱 / SNS / 카페·커뮤니티 / 기타 12. 현재 가입된 모임 수 / 그중 최근 한 달 내 실제로 나간 곳 수 `[H4]` 13. 가장 오래 다닌 모임의 기간과 참석 횟수 14. 그만둔 모임 수

**앱 사용** 15. 설치해본 모임 앱 (복수) — 소모임 / 문토 / 당근 / 프립 / 넷플연가 / 트레바리 / 기타 / 없음 16. 그중 실제로 가입까지 해본 것 17. 앱을 설치하고 아무것도 안 하고 지운 적이 있나요

**비용·거리 실적** — 가정형이 아니라 **실제 이력** `[S8, S9]` 18. 최근 나간 모임 1회 총 지출 (참가비 + 식음료 + 교통, 실제 금액) 19. 그중 참가비만 20. 집에서 모임 장소까지 편도 소요 시간 21. 지금까지 나간 모임 중 **가장 비쌌던** 1회 지출과 그 모임 성격

**마지막** 22. 지금 모임을 알아보고 계신가요 — 적극적으로 / 생각은 있음 / 아니오

# 6. 과업 관찰 (셀 A 20분 / 앵커 C 30분 / 셀 B 10분)

> **"거르는 조건"과 "관심 갖는 조건"은 질문하지 않는다.** 말로 물으면 사후 합리화가 나오고, 제외 판단은 몇 초 안에 끝나서 본인도 정확히 진술하지 못한다. 이 두 칸은 여기서만 채워진다.

## 지시문 (그대로 읽기)

> "이제 실제로 하나 골라보실 거예요. 오늘 저녁에 진짜 가입한다고 생각하시고, 평소처럼 찾아서 하나 정하는 데까지 해주세요. **가입 버튼은 누르지 마시고요.** 그리고 머릿속에 드는 생각을 소리 내서 말해주시면 돼요. '이게 뭐지', '이건 별론데' 이런 것도 다 좋아요. 제가 뭘 알려드리거나 평가하는 자리가 아니에요. 앱이 이상하면 그건 앱 문제고요."

(셀 B는 → "지금 새로 하나 더 가입한다면 어떻게 찾으실지 보여주세요.")

## 진행 규칙

- **절대 돕지 않는다.** 길을 잃어도 그대로 둔다. 그게 데이터다
- 조용해지면 → **"지금 뭐 보고 계세요?"** 이것만
- 질문을 받으면 → "저 없이 혼자 하셨으면 어떻게 하셨을 것 같아요?"
- 검색부터 직접 하게 한다. 15분 지나도 못 좁히면 그때만 후보 3개 제시

# 7. 속성 탐색 4단계 (전원, 12분)

## 왜 이 순서인가

우리가 아는 건 "이 속성이 판단에 쓰일 수도 있다"까지고, **방향도, 애초에 기준에 들어가는지도 모른다.** 먼저 물으면 두 가지가 망가진다.

- **없던 기준이 생긴다** — "뒤풀이는 어떠셨어요?"라고 물으면 그 순간 판단 항목으로 인식하고 의견을 만들어낸다
- **방향이 고정된다** — "걸리셨어요?"는 걸린 답을, "좋으셨어요?"는 좋은 답을 받는다

**자발적으로 언급하는지 여부 자체가 데이터다.** 내가 먼저 단어를 꺼내는 순간 그 데이터는 사라진다. **3단계를 1단계보다 먼저 하지 않는다.**

## 1단계 — 자발 (힌트 0)

앵커에 맞는 문장 하나만.


| 앵커    | 도입 문장                                                       |
| ----- | ----------------------------------------------------------- |
| **A** | "실제로 나가보셨던 모임 하나 떠올려 보세요. 그거 처음 알아보실 때 뭘 보셨어요? 생각나는 순서대로요." |
| **B** | "가입할까 고민했던 모임 하나 떠올려 보세요. 그 화면에서 뭘 보셨어요? 생각나는 순서대로요."       |
| **C** | "아까 여러 개 보시다가 하나 고르셨잖아요. 그때 뭘 보고 판단하셨어요? 생각나는 순서대로요."       |



| 순서  | 언급한 항목 (원문) |
| --- | ----------- |
| 1   |             |
| 2   |             |
| 3   |             |
| 4   |             |
| 5   |             |


**언급 순서가 중요도의 대리 지표다.** 7명 합산이 IA 상단 배치의 근거가 된다.

## 2단계 — 중립 프롬프트 (3회)

> "또 뭐 보신 거 있어요?" → "또요?" → "이제 없으세요?"

여기까지가 그 사람의 **실제 판단 기준 목록**이다. 여기서 안 나온 항목은 "중요하지 않다"가 아니라 **"떠오르지 않았다"**로 기록한다. 둘은 다르다.

## 3단계 — 양방향 확인

1~2단계에서 **안 나온 항목만.** 앵커에 맞는 열을 쓴다.


| 속성         | ✕ 이렇게 묻지 않는다           | ○ 앵커 A·B (회상형)           | ○ 앵커 C (화면형)                 |
| ---------- | ---------------------- | ------------------------ | ---------------------------- |
| 뒤풀이 `S5`   | "뒤풀이 있는 모임은 뭐가 걸리셨어요?" | "모임 끝나고 나서는 보통 어떻게 됐어요?" | "끝나고 뭐 하는지 얘기가 있었어요?"        |
| 연령 `S3`    | "나이대 비슷해서 좋으셨죠?"       | "그 모임엔 어떤 분들이 오셨어요?"     | "어떤 분들이 오는 모임인지 나와 있었어요?"    |
| 성비 `S4`    | "이성 많으면 부담되시죠?"        | "남녀 비율은 어땠어요?"           | "남녀 비율은 알 수 있었어요?"           |
| 실력대 `S7`   | "초보 위주면 별로죠?"          | "다들 얼마나 하시는 분들이었어요?"     | "다들 얼마나 하는 분들인지 나와 있었어요?"    |
| 인원 `S6`    | "적은 게 낫죠?"             | "몇 명이었어요?"               | "몇 명 모이는 건지 보셨어요?"           |
| 회비 `S8`    | "3만원 넘으면 부담되시죠?"       | "얼마였어요?"                 | "회비는 보셨어요?"                  |
| 반복 참석 `S2` | "같은 분들 오면 좋죠?"         | "매번 같은 분들이 오셨어요?"        | "같은 분들이 계속 오는 데인지 알 수 있었어요?" |
| 호스트 `S11`  | "리더가 잘 이끌어주면 좋죠?"      | "그 모임 리더는 뭘 하셨어요?"       | "리더가 어떤 분인지 보셨어요?"           |


**모든 항목의 후속 문장은 하나다 → "그건 어떠셨어요?"** 좋았다 / 별로였다 / **아무 생각 없었다** 셋 다 나올 수 있게 열려 있다.

**앵커 C 전용 후속**: "안 나와 있었는데, 그게 궁금하셨어요?" → 궁금했다면 L1 긍정이면서 **정보 공백의 직접 증거**. 앵커 C에서만 나오는 데이터다.

**"생각 안 해봤는데요"를 반드시 기록한다** — 그 속성이 판단 기준이 아니라는 강한 증거다. 페르소나 항목 중 몇 개가 여기로 떨어질 가능성이 높다.

**앵커 C의 한계**: S8·S9의 임계값은 실제 지불·이동에서만 나온다. 앵커 C는 `U`로 두고 4단계로만 확인한다. **가정형으로 채우지 않는다.**

## 4단계 — 카드 소트 (5분)

카드 12장: 활동 종류 / 연령대 / 성비 / 인원 규모 / 회비 / 위치·이동시간 / 시작·종료 시간 / 뒤풀이 유무 / 최근 활동 게시글 / 같은 사람이 계속 오는지 / 참가자 실력대 / 호스트 스타일

1. "이 중에 **없으면 아예 판단이 안 되는 것**만 골라주세요" → **필수군**
2. 나머지 중 "있으면 좋은데 없어도 되는 것" → **보조군**
3. 나머지 → **무관군**
4. 필수군만 놓고 "1순위부터 순서대로요"
5. 필수군 각 카드마다 → **"이게 어떤 내용이면 그 모임 바로 거르세요?"** ← 방향과 임계값이 여기서 나온다


| 카드  | 필수/보조/무관 | 순위  | 어떤 값이면 제외하는가 (원문) |
| --- | -------- | --- | ----------------- |
|     |          |     |                   |


**카드는 참가자가 "이런 것도 있었네" 하고 새로 인식하게 만든다.** 4단계 결과는 1~2단계와 **분리해서** 기록하고, 보고서에도 "자발 언급 / 카드 제시 후"를 구분해 표기한다.

- 본인 폰 → iOS는 제어센터의 화면 기록, Android 11 이상은 빠른 설정의 화면 녹화. **마이크를 켜야 발화가 함께 녹음된다**
- 대면이면 삼각대로 손과 화면을 함께 찍는 편이 낫다. **손가락이 어디서 멈추는지는 화면 녹화에 안 남는다**
- 시작 전 알림 끄기 안내 필수
