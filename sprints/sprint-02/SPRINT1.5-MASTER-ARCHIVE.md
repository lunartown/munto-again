## 0. 이 아카이브의 사용 규칙

- `확인됨`: 실제 화면 캡처와 사용자 근거(인터뷰·리뷰·모집글)가 모두 있는 사실
- `부분 확인`: 화면 캡처 또는 사용자 근거 중 한쪽만 있는 사실
- `가설`: 연구자가 캡처들을 근거로 연결한 설명이며 직접 근거가 부족함
- `미확인`: 화면 또는 근거를 아직 확보하지 못함
- 화면 캡처는 CS-01~CS-62 번호를 부여했고, 실제 확보한 파일은 39장이다
  (`../../archive/research/data/current_state/screenshots/`).
- Sprint 1.5는 새로운 문제를 찾는 리서치가 아니라, Sprint 1에서 정의한 문제를 문토의
  현재 화면·흐름에 연결하는 현재 상태 분석이다.
- 이 단계의 결과물은 기능 확정이 아니라 Sprint 2가 다룰 리뉴얼 범위를 좁히기 위한
  근거다.

## 1. 왜 필요한가

Sprint 1에서 다음 문제를 확인했다.

> 사용자는 클럽에 가입하기 전에 활동 목적·반복 방식·구성원 분위기·운영 규칙·최근 활동
> 이력을 비교하기 어렵다.

이 문제만으로는 어떤 화면을 어떻게 바꿔야 하는지 결정할 수 없다. Sprint 1.5에서는
문토의 현재 플로우에서 사용자가 어떤 정보를 보고, 어떤 행동을 하며, 어느 순간에 판단을
멈추는지 확인한다.

## 2. 분석 목표

1. 문토에서 클럽을 처음 고르는 사용자의 현재 여정을 재현한다.
2. 각 단계에서 제공되는 정보와 제공되지 않는 정보를 기록한다.
3. Sprint 1의 인터뷰·리뷰 근거를 현재 플로우의 문제 지점에 연결한다.
4. 문토가 통제할 수 있고 Sprint 2 화면으로 구체화할 수 있는 문제를 우선순위화한다.
5. 하나의 핵심 시나리오와 최소 기능 범위를 정한다.

## 3. 분석 범위

### 3.1 우선 여정

```text
클럽 탐색 → 검색·필터 → 클럽 상세 확인 → 활동 적합성·운영 지속성 판단
  → 가입 질문 → 승인·가입 완료 → 채팅·정기 활동
```

### 3.2 보조 여정

현재 구조를 이해하기 위해 확인하되, Sprint 2의 핵심 화면 범위에는 넣지 않는다.

- 소셜링·챌린지의 상세 참여 흐름
- 클럽 개설·운영자 정보 입력
- 후기·평점 작성
- 취소·환불·신고·퇴출
- 문제 발생 후 처리 상태 확인

### 3.3 이번 단계에서 제외

- 문토 전체 앱의 모든 화면 분석
- 추천 알고리즘의 내부 로직 추정
- 소개팅·파티 모임의 제거 여부 결정
- 경쟁 서비스의 기능을 그대로 복사하는 벤치마크
- 아직 확인하지 않은 기능을 현재 사실처럼 기록

## 4. 조사 방법

2026-08-02에 소셜링·클럽·챌린지·홈·검색·카테고리·찜 화면을 신규 사용자 관점으로
캡처했다.

1. 지역과 관심사를 정하지 않은 상태에서 목록을 연다.
2. 클럽 검색·필터·정렬로 후보를 좁힌다.
3. 클럽 후보 2~3개의 상세 페이지를 비교한다.
4. 가입 질문과 활동비가 있는 경우의 결제 직전까지 진행한다.
5. 승인·가입 완료·채팅·정기 활동 화면이 어디에서 이어지는지 확인한다.

실제 확인이 어려운 단계는 `확인 필요`로 표시하고 추정으로 채우지 않았다. 참석·체크인·
후기 완료 화면과 챌린지 전용 대기·환불 화면은 아직 확보하지 못했다.

## 5. 진입점 구조

`검색`·`카테고리`·`프로모션`·`찜`은 앱 밖에서 독립적으로 시작하는 지점이 아니다. 홈과
공통 탐색 영역에서 열리는 조작 표면이며, 각 목록 화면에도 검색·필터·정렬 조작이
반복된다.

| 진입점 유형 | 캡처 | 도착 콘텐츠 | 현재 확인 내용 | 대표 플로우 |
|---|---|---|---|---|
| 홈·추천 | CS-01 | 소셜링·클럽·콘텐츠 큐레이션 | 여러 콘텐츠 유형이 한 화면에 함께 노출됨 | 콘텐츠 유형별 플로우로 분기 |
| 프로모션·큐레이션 | CS-02 | 특정 주제의 소셜링 목록 | 기간·주제 기반 목록. 클럽·챌린지 홈에는 이 섹션이 없음을 직접 확인 | 소셜링 전용 진입 |
| 카테고리 | CS-01→CS-03 | 관심사별 목록 | 홈에서 카테고리 진입 후 선택 | 유형별 목록으로 분기 |
| 검색 | CS-01→CS-04 | 키워드 검색 결과 | 홈에서 검색 진입 후 검색어 입력 | 유형별 목록으로 분기 |
| 소셜링 탭 | CS-01→CS-10~24 | 일회성 모임 | 목록에서 검색·필터 가능 | 소셜링 참여 |
| 클럽 탭 | CS-01→CS-30~41 | 장기 모임 | 목록에서 검색·필터·정렬 가능 | 클럽 가입·유지 |
| 챌린지 탭 | CS-60~62 | 챌린지 | 홈·상세·참여 진입 확인 | 챌린지 참여 |
| 찜 | CS-50 | 저장한 콘텐츠 | 찜한 목록으로 재진입 | 기존 콘텐츠 플로우로 합류 |

대표 플로우로 통합:

```text
홈·추천·프로모션·카테고리·검색·찜
             ↓
     콘텐츠 목록 / 검색 결과
       ├── 소셜링 상세 → 신청·결제 → 신청·취소
       ├── 클럽 상세 → 가입 질문 → 대기·완료 → 채팅
       └── 챌린지 상세 → 참여
```

분석 범위 결정: 진입점 인벤토리에는 네 유형을 모두 기록하되, 상세 분석은 소셜링과
클럽을 우선 비교한다(참여 목적과 상태 변화가 다름). 챌린지는 구조만 확인하고 Sprint 2
대표 시나리오로 선택되지 않으면 별도 개선안을 만들지 않는다. 추천·프로모션·카테고리·
검색은 독립 제품 플로우가 아니라 콘텐츠 목록으로 들어가는 진입 표면으로 관리한다.

## 6. 핵심 판단 — 선형 퍼널이 아니다

문토의 현재 구조는 `진입점 → 하나의 목록 → 소셜링·클럽·챌린지 분기`라는 한 줄로
연결하면 실제 구조를 왜곡한다. 두 개를 분리해야 한다.

1. 탐색 구조: 어디서 어떤 콘텐츠로 들어가는가
2. 참여 상태 플로우: 콘텐츠 유형별로 참여 후 상태가 어떻게 바뀌는가

**콘텐츠 유형은 완전히 분리된 통로가 아니다.** 클럽 목록(홈)에는 "클럽 소셜링"·"최근
소셜링이 열린 클럽" 섹션이 있고(CS-30), 여기서 클럽이 개설한 소셜링을 선택하면 소셜링과
동일한 신청·결제·취소·채팅 플로우로 이어진다(CS-25, CS-26 실증). 즉 소셜링 상세로
들어가는 진입점은 소셜링 탭 계열뿐 아니라 클럽 목록에서도 발생한다.

## 7. 콘텐츠 유형별 참여 상태

### 7.1 소셜링 — 일회성 신청·결제 상태

```text
소셜링 목록 → 소셜링 상세 → 호스트 질문 답변 → 결제 금액·할인·환불 규정 확인
  → 신청 완료 ↘ 취소·취소 완료
```

확인된 사실:

- 상세에서 설명·참여자·일정·비용을 확인하고, 신청 전 호스트 질문에 답한다.
- 결제 화면에 참가비, 얼리버드 할인, 비용 구성, 환불 규정, 결제 수단, 동의가 있다.
- 소셜링도 승인제가 있다. 신청 완료 후 24시간 내 호스트가 수락하지 않으면 자동으로
  신청이 취소되고 참가비는 전액 환불된다(CS-21).
- 마이페이지 > 모임내역에는 소셜링·클럽·챌린지 공통으로 `참여`(신청해 종료, 앵콜 요청
  가능) / `대기`(승인 대기, 호스트 문의·대기 취소) / `진행중`(참여자 상태가 아니라 **내가
  호스트로 개설한 모임** 목록) 세 구획이 있다(CS-05).
- 승인 완료 후 모임별 채팅방이 자동 생성되고, 참여자 입장 로그·위치 공유가 표시된다
  (CS-25). 진입 경로는 모임내역 참여 카드의 "채팅방 입장" 버튼이다.
- 취소는 두 단계다. ① 승인 대기 중 취소(CS-22): 경고 점수 없이 전액 환불. ② 승인 확정
  후 취소(CS-26): 누적 경고 점수 제도 적용 — 호스트 합의 없이 2일 이내·당일 취소 시 각
  2점, 60일 누적 5점 이상 7일 정지·7점 14일·10점 30일·20점 이상 영구 정지. 환불은 결제
  후 30분 이내/승인 대기 중 취소/참여 거절·승인 후 퇴출/진행일 4일 전까지는 전액, 3일
  전부터는 불가.
- 실제 참석·체크인, 후기 작성 화면은 **미확인**.
- 소셜링의 비승인제 존재 여부는 **미확인** — 확보한 "신청 완료" 캡처(CS-21)가 승인제
  사례 하나뿐이다. 클럽은 승인제(CS-39)·비승인제(CS-40) 둘 다 확보했다.

### 7.2 클럽 — 장기 가입·관계 유지 상태

```text
클럽 목록 → 클럽 상세 → 가입 질문 확인·답변 입력 → 가입 대기 → 가입 완료 → 채팅방 진입
```

확인된 사실:

- 클럽도 활동비가 있을 수 있다. 유료 클럽의 실제 결제 화면도 확인됨 — 가입 질문 답변
  다음, 승인 여부가 결정되기 전에 "결제·환불 확인" 단계가 있다.
- 소셜링도 무료인 경우가 있다(CS-26, 결제·환불 금액 0원). 유형과 유·무료가 고정 관계가
  아니라는 근거다.
- 가입 질문은 플랫폼 표준 항목이 아니라 호스트가 직접 설정하는 커스텀 질문이다(CS-37
  MBTI 클럽 사례, CS-38 거주지·연령대 자격 요건 사례). 표준 입력 형식이 없다.
- 클럽 상세에는 "클럽소셜링" 섹션이 있어 이 클럽이 개설한 소셜링으로 바로 이어진다
  (CS-36). 클럽 목록(홈)에도 여러 클럽을 묶은 발견 피드가 별도로 있다(CS-30).
- **가입 완료 후에도 모임내역에서 탈퇴할 수 있다**(CS-42 "참여 취소" 버튼). 탈퇴 시 경고
  점수·환불 여부 등 구체적 정책은 **미확인**.
- 클럽도 승인제가 있다 — 24시간 내 미승인 시 자동취소·전액환불(CS-39), 소셜링과 동일한
  구조다. **비승인제 클럽도 실제로 확인됨**(CS-40, 질문 제출 직후 즉시 가입 완료). 클럽
  마다 승인 여부가 다르다는 것은 가정이 아니라 확인된 사실이다.
- 클럽 상세의 "안내사항"에 "299/300명 · 승인제"처럼 승인제 여부가 명시적으로 표시된다
  (CS-36), 챌린지(CS-61)와 동일한 위치·형식이다.
- **거절 사유 불투명 문제의 실사용자 증거.** CS-36 댓글에 서로 다른 시점(2025.9.14,
  2025.12.21)의 두 사용자가 "가입 거절 이유를 알 수 있을까요?"라고 공개적으로 묻는다.
  한 명은 "엠비티아이가 달라서 그런건가요?"라며 이유를 추측만 한다. Sprint 1 핵심 문제
  (문제 발생 후 책임·해결 상태 불명확)의 직접적인 실사용자 증거다.
- 채팅방 안에 "소셜링" 탭이 별도로 있다(CS-41) — 일정 변경 공지·멤버 문의가 이 탭
  주변에서 오간다. "클럽 피드" 기능도 있어 활동 사진을 클럽원끼리 공유한다.
- 클럽 검색 정렬에 "클럽 소셜링 많은 순"이 있다(CS-35) — 클럽↔소셜링 연결이 부차 기능이
  아니라 클럽 랭킹의 정식 기준이다.
- 클럽 검색·필터의 카테고리 구성은 소셜링 모집글 분석에 쓰인 카테고리와 동일하다
  (CS-32). 온라인/오프라인 토글도 동일하다(CS-34).

### 7.3 챌린지 — 목표·기간 기반 참여 상태

```text
챌린지 홈 → 챌린지 상세 → 참여 질문 → 참여 신청
```

확인된 사실:

- 상세에는 기간, 인증 방식, 참여 대상, 멤버 정보, 댓글이 있다.
- 챌린지도 승인제다(CS-61 "5/8명·승인제"). 무료 챌린지도 실제로 있다(참가비 0원).
- **참여 완료 상태를 확인함.** 매일 인증(활동 촬영 업로드)으로 진행되며, 정해진 기간이
  끝나면 참가자들이 실제로 만나는 "티타임"(오프라인 모임)으로 마무리된다(CS-61). 가입
  질문(CS-62)도 "이름/나이/사는곳(티타임 장소 정하기 위함)/직업"처럼 이 오프라인 모임을
  전제로 구성돼 있다.
- **승인 대기·자동취소·거절·대기취소 구조는 챌린지 전용 캡처로 확인된 것이 아니라
  가설이다.** 소셜링(CS-21)·클럽(CS-39)이 "24시간 내 미승인 시 자동취소·전액환불"
  문구를 토씨까지 동일하게 쓰는 것으로 볼 때 유형과 무관한 플랫폼 공통 정책일
  가능성이 크지만, 챌린지 대기 화면 자체는 캡처하지 못했다.

### 7.4 콘텐츠 유형 간 교차 구조

소셜링·클럽·챌린지는 독립된 세 갈래가 아니라 서로 얽혀 있다 — 클럽은 자체적으로
소셜링을 개설하고, 챌린지도 종료 시점에 오프라인 "티타임"으로 이어진다. 두 사실 모두
"구조화 안 된 정보"라는 Sprint 1 가설과 관련된 실제 증거일 수 있다 — 소셜링·클럽·
챌린지라는 카테고리 탭 구분이 사용자가 실제로 겪는 참여 경로와 정확히 일치하지 않는다.

## 8. 다이어그램 작성 규칙

### 8.1 재작성 규칙

- 영역 A(탐색 구조): 탐색 표면(홈·추천/프로모션/카테고리/검색/찜) → 콘텐츠 유형(소셜링·
  클럽·챌린지) → 각 유형의 상세 화면. 모든 조합을 선으로 연결하지 않고 다대다 관계를
  요약 구조로 표시하며, 실제 이동 예시는 대표 1~2개만 연결한다.
- 영역 B(참여 상태 플로우): 세 유형을 서로 다른 가로 레인으로 분리하고 레인 사이에
  연결선을 만들지 않는다. 파랑=소셜링, 초록=클럽, 노랑=챌린지, 회색=탐색 표면·공통 화면,
  빨강=미확인 또는 추가 확인 필요.

### 8.2 세 mermaid 파일 간 구조 일관성 규칙 (2026-08-02 점검)

`current-state-socialing.mmd`, `current-state-club.mmd`, `current-state-challenge.mmd`는
같은 종류의 사실을 다른 방식으로 표현하지 않는다.

- 상세 페이지 안의 하위 섹션(멤버 미리보기·활동비·참가 조건 등)은 별도 노드로 쪼개지
  않는다 — `상세 정보 확인` 한 노드로 충분하다. 예외는 소셜링 "참여 확정 멤버"(CS-17,
  뒤로가기가 있는 별도 페이지).
- `마이페이지·모임내역` 참조 노드는 세 파일에서 동일한 문구를 쓴다.
- 모임내역 상태 확인 지점은 **승인 대기 중**과 **승인 확정 후** 두 곳 모두에 연결한다.
- 유형별로 실제 캡처가 다른 부분(클럽의 승인제/비승인제 분기, 챌린지의 매일 인증·
  티타임)은 강제로 맞추지 않고 그대로 다르게 유지한다.
- "거절"은 클럽 한정이 아니라 승인제 자체의 일반 메커니즘으로 판단해 소셜링에도
  반영했다. 승인 완료 시점도 "참여 확정"(소셜링)/"가입 완료"(클럽)처럼 별도 상태 노드로
  통일했다.
- **참가비 유무는 분기(다이아몬드)로 표현**한다 — "참가비/활동비 있음?" 결정 → 예: 결제·
  환불 확인 → 아니오: 다음 단계로 직행. 세 유형 모두 유·무료가 실제로 갈린다는 근거가
  있어 분기 처리가 타당하다.
- "신청 폼"은 별도 단계로 두지 않는다 — "예" 선택 후 바로 호스트 질문 답변으로 이어진다.

## 9. 클럽 흐름 — Sprint 1 근거 매핑

문토의 현재 **클럽 흐름**에서 발견한 문제를 Sprint 1 근거와 연결한다. 리뷰·인터뷰·
모집글의 반복 근거와 실제 화면 확인을 섞지 않고 출처를 구분한다.

| 플로우 단계 | 현재 화면에서 확인한 사실 | 사용자 문제/행동 결과 | 인터뷰 카드 | 리뷰 원문 | 모집글 근거 | 판정 |

## 10. 아직 모르는 것

- 추천 카드에서 상세로 이동할 때의 정확한 화면 전환
- 소셜링 실제 참석·체크인, 후기 작성 상태 (채팅방 진입과 취소·환불 정책은 확인됨)
- 검색 결과의 챌린지·피드 상세 흐름
- 클럽 채팅방 "소셜링" 탭과 "클럽 피드"의 실제 화면 (문구·문의로만 확인, 탭 내부 화면은
  아직 캡처하지 않음)
- 챌린지의 취소·포기 플로우 전체 (승인제 라벨만 확인됨. 대기 중 취소나 24시간
  자동취소가 있는지는 캡처 없음)
- 소셜링의 비승인제 사례
- 클럽 탈퇴 시 경고 점수·환불 정책
- 각 진입점에서 사용자가 실제로 비교하는 정보 (진입점 인벤토리 후속 기록)
- 같은 콘텐츠가 여러 진입점에서 어떻게 다르게 노출되는지 비교
- 소셜링·챌린지 흐름의 Sprint 1 근거 매핑 (현재는 클럽 흐름만 완료)

이 항목들은 추정으로 다이어그램·문서에 넣지 않고 `미확인`으로 표시한다.

## 11. 우선순위 결정 기준

각 문제를 다음 기준으로 1~3점 평가한다.

| 기준 | 1점 | 2점 | 3점 |
|---|---|---|---|
| 사용자 영향 | 불편이 작음 | 선택을 지연시킴 | 포기·불신·손실로 이어짐 |
| 근거 강도 | 연구자 해석 | 한 자료에서 반복 | 인터뷰·리뷰·현재 화면에서 교차 확인 |
| 플랫폼 통제 가능성 | 외부 요인 | 일부 통제 | 문토 화면·정책으로 직접 통제 |
| Sprint 2 설계 적합성 | 후속 과제 | 일부 화면에 반영 가능 | 핵심 화면으로 명확히 구체화 가능 |

총점이 높은 문제를 Sprint 2의 핵심 문제로 채택한다. 점수만으로 결정하지 않고, 제외한
문제와 이유도 함께 기록한다.
