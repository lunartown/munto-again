# 문토 Current-State 모델 v2

> 목적: FigJam 다이어그램을 다시 그리기 전에, 캡처로 확인한 문토의 실제 구조를 먼저
> 분리해서 정의한다.
>
> 상태: 분석 초안. 이 문서 검토 후 FigJam을 재작성한다.

## 1. 핵심 판단

문토의 현재 구조는 하나의 선형 퍼널이 아니다.

```text
여러 탐색 표면
  → 여러 콘텐츠 유형의 목록·상세
  → 유형별로 다른 참여 상태 전이
```

따라서 `진입점 → 하나의 목록 → 소셜링·클럽·챌린지 분기`로 한 줄에 연결하면 실제
구조를 왜곡하고 선이 복잡해진다. 다이어그램은 아래 두 개를 분리해야 한다.

1. 탐색 구조: 어디서 어떤 콘텐츠로 들어가는가
2. 참여 상태 플로우: 콘텐츠 유형별로 참여 후 상태가 어떻게 바뀌는가

## 2. 캡처에서 확인한 탐색 구조

### 2.1 탐색 표면

| 탐색 표면 | 캡처 | 역할 | 별도 참여 플로우인가 |
|---|---|---|---|
| 홈·추천 | CS-01, CS-10, CS-30, CS-60 | 여러 콘텐츠를 섹션·탭·추천 목록으로 노출 | 아니오. 콘텐츠로 들어가는 표면 |
| 프로모션·큐레이션 | CS-02 | 특정 기간·주제의 목록으로 진입. 클럽·챌린지 홈에는 이 섹션이 없음을 직접 확인함(소셜링 전용) | 아니오. 결과 목록의 변형 |
| 카테고리 | CS-03 | 관심사별 콘텐츠 탐색 | 아니오. 결과 목록의 변형 |
| 검색 | CS-04, CS-11, CS-31 | 키워드 입력 후 콘텐츠 유형별 결과 확인 | 아니오. 결과 목록의 변형 |
| 찜 | CS-50 | 저장한 콘텐츠로 재진입 | 아니오. 기존 콘텐츠 플로우로 합류 |

**콘텐츠 유형은 완전히 분리된 통로가 아니다.** 클럽 목록(홈)에는 "클럽 소셜링"·
"최근 소셜링이 열린 클럽" 섹션이 있고(CS-30), 여기서 클럽이 개설한 소셜링을 선택하면
`current-state-socialing.mmd`와 동일한 신청·결제·취소·채팅 플로우로 이어진다(CS-25,
CS-26 실증). 즉 소셜링 상세로 들어가는 진입점은 소셜링 탭 계열뿐 아니라 클럽 목록에서도
발생한다.

### 2.2 콘텐츠 유형

| 유형 | 목록/홈 | 상세 | 참여 버튼·상태 |
|---|---|---|---|
| 소셜링 | CS-10~14 | CS-15~17 | 신청하기 → 질문 → 결제 → 완료·취소 (CS-18~24) |
| 클럽 | CS-30~35 | CS-36 | 클럽 신청하기 → 질문 → 대기·완료 → 채팅 (CS-37~41) |
| 챌린지 | CS-60 | CS-61 | 신청하기 → 질문 입력 화면 확인 (CS-62) |

### 2.3 검색은 별도 구조로 기록

검색 화면에는 검색어 입력·최근 검색·추천 검색어가 있고, 결과 화면은 소셜링·클럽·
챌린지·피드 유형 탭으로 나뉜다. 따라서 검색을 특정 콘텐츠 유형의 앞 단계로 고정하지
않고, 여러 유형으로 연결되는 탐색 표면으로 표시한다.

## 3. 콘텐츠 유형별 참여 상태

### 3.1 소셜링: 일회성 신청·결제 상태

```text
소셜링 목록
  → 소셜링 상세
  → 호스트 질문 답변
  → 결제 금액·할인·환불 규정 확인
  → 신청 완료
  ↘ 취소·취소 완료
```

확인된 정보:

- 상세에서 설명·참여자·일정·비용을 확인한다.
- 신청 전 호스트 질문에 답한다.
- 결제 화면에 참가비, 얼리버드 할인, 비용 구성, 환불 규정, 결제 수단, 동의가 있다.
- 신청 완료와 취소 완료 상태가 캡처되어 있다.
- 소셜링도 승인제가 존재한다. 신청 완료 후 24시간 내 호스트가 수락하지 않으면
  자동으로 신청이 취소되고 참가비는 전액 환불된다(CS-21).
- 마이페이지 > 모임내역에 소셜링·클럽·챌린지 공통으로 `참여`(참여자로 신청해 종료,
  앵콜 요청 가능) / `대기`(참여자로 신청해 승인 대기, 호스트 문의·대기 취소) / `진행중`
  세 구획이 있다(CS-05). `진행중`은 참여자 상태가 아니라 **내가 호스트로 개설한 모임**
  목록이다(빈 상태 문구 "내가 진행하는 소셜링은 여기에서 확인할 수 있어요"로 확인).
  참여자 우선 여정과는 무관하므로 더 확인하지 않는다.
- 승인 완료 후 모임별 채팅방이 자동 생성된다. 문토봇이 "모임 채팅방이 생겼어요"라고
  안내하고, 참여자 입장 로그와 위치 공유가 채팅방에 표시된다(CS-25). 진입 경로는
  모임내역의 참여 카드에 있는 "채팅방 입장" 버튼이다(CS-42, 클럽 사례로 확인).
- 취소 화면은 두 단계로 나뉜다. ① 승인 대기 중 취소(CS-22): 경고 점수 없이 전액 환불.
  ② 승인 확정 후 취소(CS-26): 누적 경고 점수 제도가 적용된다 — 호스트 합의 없이
  2일 이내·당일 취소 시 각 2점, 60일 누적 5점 이상 7일 정지·7점 14일·10점 30일·20점
  이상 영구 정지. 환불은 결제 후 30분 이내/승인 대기 중 취소/참여 거절·승인 후 퇴출/
  진행일 4일 전까지는 전액, 3일 전부터는 불가.
- 실제 참석·체크인, 후기 작성 화면은 아직 확인하지 않았다.
- **소셜링도 비승인제가 있는지는 미확인.** 클럽은 승인제(CS-39)와 비승인제(CS-40) 사례를
  각각 확보해 실제로 둘 다 존재함을 확인했지만, 소셜링은 "신청 완료" 캡처가 CS-21 하나뿐이고
  그 사례가 승인제였다. 클럽과 같은 구조일 것이라는 추정일 뿐, 소셜링 비승인제 사례는
  아직 확보하지 못했다.

### 3.2 클럽: 장기 가입·관계 유지 상태

```text
클럽 목록
  → 클럽 상세
  → 가입 질문 확인·답변 입력
  → 가입 대기
  → 가입 완료
  → 채팅방 진입
```

확인된 정보:

- 상세에서 클럽 소개, 멤버, 활동 게시물, 댓글, 참가 조건을 확인한다.
- 클럽도 활동비가 있을 수 있다. CS-36(NF 저장소)은 안내사항에 "무료"로 명시돼 있지만,
  가입 대기 화면(CS-39)의 환불 안내는 "활동비는 전액 환불돼요"라고 표현해 유료 클럽의
  존재를 전제한다. **유료 클럽의 실제 결제 화면도 확인됨** — 소셜링과 동일하게
  가입 질문 답변 다음, 승인 여부가 결정되기 전에 "결제·환불 확인" 단계가 있다.
- **소셜링도 무료인 경우가 있다.** CS-26(확정 후 취소 화면)에서 결제 금액·환불 금액이
  모두 0원인 사례가 확인됐다 — 소셜링이 항상 유료라는 가정도 틀렸다.
- 가입 질문은 플랫폼이 정한 표준 항목이 아니라 호스트가 직접 설정하는 커스텀 질문이다.
  CS-37 사례(MBTI 클럽)에서는 MBTI·성별·나이대·기대·배려 관련 질문을 넣었지만, 이는 이
  클럽의 개별 선택이지 가입 질문의 표준 구성이 아니다.
- 클럽 상세에는 "클럽소셜링" 섹션이 있어 이 클럽이 개설한 소셜링으로 바로 이어진다(CS-36).
  클럽 목록(홈)에도 여러 클럽을 묶은 "클럽 소셜링" 발견 피드가 별도로 있다(CS-30).
- 가입 완료 후 채팅방 진입이 제공된다.
- **가입 완료 후에도 모임내역에서 탈퇴할 수 있다.** CS-42의 "참여중" 카드(이미 가입된
  상태)에 "채팅방 입장"과 나란히 "참여 취소" 버튼이 있다. 다만 탈퇴 시 경고 점수·환불
  여부 등 구체적 정책은 확인하지 못했다.
- 클럽도 승인제가 존재한다. "승인제 클럽은 신청 후 24시간 내에 호스트가 수락하지 않으면
  자동으로 신청이 취소되고 활동비는 전액 환불된다"는 문구가 가입 대기 화면에 있다(CS-39).
  소셜링과 동일한 구조다.
- **비승인제 클럽도 실제로 확인됨.** 다른 클럽(CS-40)은 가입 대기 화면 없이 질문 제출
  직후 바로 "클럽 참여가 완료됐어요!"로 끝나고 채팅방 입장 팝업이 떴다. 즉 클럽마다
  승인 여부가 다르다는 것이 확인됐다(가정이 아니라 사실).
- 클럽 상세의 "안내사항"에 "299/300명 · 승인제"처럼 승인제 여부가 명시적으로 표시된다
  (CS-36). 챌린지(CS-61 "5/8명·승인제")와 동일한 위치·형식이다.
- **거절 사유 불투명 문제의 실사용자 증거.** CS-36 댓글에 서로 다른 시점(2025.9.14,
  2025.12.21)의 두 사용자가 "가입 거절 이유를 알 수 있을까요?"라고 공개적으로 묻고
  있다. 한 명은 "엠비티아이가 달라서 그런건가요?"라며 이유를 추측만 한다. Sprint 1
  핵심 문제(문제 발생 후 책임·해결 상태 불명확)의 직접적인 실사용자 증거다.
- 가입 질문 화면(CS-37)에는 호스트가 명시적으로 거절할 수 있다는 안내("결이 맞는 분만
  모시고 있어요, 거절 양해 바랍니다")와 가입 완료 후에도 별도 공지를 이행해야 가입이
  완료된다는 조건("합류 후, 공지 이행해주셔야 가입 완료됩니다")이 있다.
- 가입 질문 형식은 클럽마다 완전히 다르다. CS-38 사례는 "나이(년생)/mbti/성별/거주지"를
  특정 형식으로 요구하고("거주지는 서울/경기만 적지 말고 전철역/구까지") 연령대 자격
  요건(02년생~92년생)도 걸어뒀다. 표준 입력 형식이 없다는 근거다.
- **채팅방 안에 "소셜링" 탭이 별도로 있다(CS-41).** 정기 일정·활동 참여 상태로 아직
  확인 못 했던 항목이 바로 이것이다 — 일정 변경 공지와 멤버 문의가 이 탭 주변 채팅으로
  오간다(예: "8월 10일 일정 취소, 8월 6일로 변경"). 별도로 "클럽 피드" 기능도 있어
  소셜링 활동 사진을 클럽원끼리 공유한다.
- 클럽 검색 결과 정렬 옵션에 "**클럽 소셜링 많은 순**"이 있다(CS-35). 클럽이 소셜링을
  얼마나 여는지가 클럽 랭킹의 정식 기준이라는 뜻으로, 클럽↔소셜링 연결이 부차 기능이
  아니라 핵심 기능임을 보여준다.
- 클럽 검색·필터의 카테고리 구성(파티·푸드드링크·자기계발·N잡재테크·외국어·취미·
  소셜게임·액티비티·문화예술·여행나들이·동네또래·연애사랑)은 소셜링 모집글 분석에
  쓰인 카테고리와 동일하다(CS-32). 온라인/오프라인 토글도 동일하게 있다(CS-34).

### 3.2.1 콘텐츠 유형 간 교차 구조

소셜링·클럽·챌린지는 독립된 세 갈래가 아니라 서로 얽혀 있다.

- 클럽은 자체적으로 소셜링을 개설한다(3.2 참고).
- 챌린지도 종료 시점에 오프라인 "티타임" 모임으로 이어진다(3.3 참고).

두 사실 모두 "구조화 안 된 정보"라는 Sprint 1 가설(H1)과 관련된 실제 증거일 수 있다 —
소셜링·클럽·챌린지라는 카테고리 탭 구분이 사용자가 실제로 겪는 참여 경로와 정확히
일치하지 않는다는 뜻이기 때문이다.

### 3.3 챌린지: 목표·기간 기반 참여 상태

```text
챌린지 홈
  → 챌린지 상세
  → 참여 질문
  → 참여 신청
```

확인된 정보:

- 챌린지 홈에는 인기 챌린지, 멤버 후기, 전체 챌린지 목록이 함께 노출된다.
- 상세에는 기간, 인증 방식, 참여 대상, 멤버 정보, 댓글이 있다.
- 챌린지도 승인제다. CS-61 사례는 "5/8명·승인제"로 표시돼 있다. 무료 챌린지도 실제로
  있다(CS-61, 참가비 0원) — 챌린지가 항상 유료라는 가정은 틀렸다.
- **참여 완료 상태를 확인함.** 매일 인증(활동을 촬영해 업로드)으로 진행되며, 2주 등
  정해진 기간이 끝나면 참가자들이 실제로 만나는 "티타임"(오프라인 모임)으로 마무리된다
  (CS-61). 가입 질문(CS-62)도 "이름/나이/사는곳(티타임 장소 정하기 위함)/직업"처럼
  이 오프라인 모임을 전제로 구성돼 있다.
- 참가비도 상세 안내사항에 표시된다(무료 확인됨, CS-61). 소셜링·클럽과 같은 위치.
- **승인 대기·자동취소·거절·대기취소 구조는 챌린지 전용 캡처로 확인된 것이 아니라
  추론으로 다이어그램에 반영했다.** 소셜링(CS-21)과 클럽(CS-39)이 "24시간 내 미승인
  시 자동취소·전액환불" 문구를 토씨까지 동일하게 쓰는 것으로 볼 때 유형과 무관한 플랫폼
  공통 정책일 가능성이 크고, 챌린지도 승인제임이 확인됐으므로 같은 구조를 적용했다.
  다만 챌린지 대기 화면 자체는 캡처하지 못했으므로 확정 사실은 아니다.

## 4. 다이어그램 재작성 규칙

### 영역 A — 탐색 구조

```text
탐색 표면
홈·추천 / 프로모션 / 카테고리 / 검색 / 찜
                    ↓
콘텐츠 유형
소셜링 목록 / 클럽 목록 / 챌린지 홈
                    ↓
각 유형의 상세 화면
```

탐색 표면끼리와 콘텐츠 유형끼리 모든 조합을 선으로 연결하지 않는다. 다대다 관계임을
표시하는 요약 구조로 만들고, 실제 이동 예시는 대표 1~2개만 연결한다.

### 영역 B — 참여 상태 플로우

세 유형을 서로 다른 가로 레인으로 분리한다. 레인 사이에 연결선을 만들지 않는다.

- 파랑: 소셜링
- 초록: 클럽
- 노랑: 챌린지
- 회색: 탐색 표면·공통 화면
- 빨강: 미확인 또는 추가 확인 필요

## 5. 현재 분석에서 아직 모르는 것

- 추천 카드에서 상세로 이동할 때의 정확한 화면 전환
- 소셜링 실제 참석·체크인, 후기 작성 상태 (채팅방 진입과 취소·환불 정책은 확인됨)
- 검색 결과의 챌린지·피드 상세 흐름
- 클럽 채팅방 "소셜링" 탭과 "클럽 피드"의 실제 화면 (문구·문의로만 확인, 탭 내부 화면
  자체는 아직 캡처하지 않음)
- 챌린지의 취소·포기 플로우 전체 (승인제 라벨만 확인됨. 소셜링·클럽처럼 대기 중 취소나
  24시간 자동취소가 있는지는 캡처 없음)

이 항목들은 추정으로 다이어그램에 넣지 않고 `미확인`으로 표시한다.

## 6. 세 파일 간 구조 일관성 점검 (2026-08-02)

세 개의 참여 상태 mmd 파일(`current-state-socialing.mmd`, `current-state-club.mmd`,
`current-state-challenge.mmd`)은 같은 종류의 사실을 다른 방식으로 표현하지 않는다.
아래는 교차 점검으로 맞춘 공통 규칙이다.

- 상세 페이지 안의 하위 섹션(멤버 미리보기·활동비·참가 조건 등)은 별도 노드로 쪼개지
  않는다. `상세 정보 확인` 한 노드로 충분하다 — 클럽 "가입 멤버"(CS-36), 챌린지
  "멤버소개"(CS-61), 클럽 활동비 안내는 전부 상세 페이지 내부 섹션이지 별도 화면이
  아니다. 예외는 소셜링 "참여 확정 멤버"(CS-17) — 이건 뒤로가기 버튼이 있는 별도
  페이지로 실제 이동하는 화면이라 노드로 유지한다.
- `마이페이지·모임내역` 참조 노드는 세 파일에서 동일한 문구
  ("참여/대기/진행중\n진행중은 호스트 개설 목록, 참여자 무관")를 쓴다.
- 모임내역 상태 확인 지점은 **승인 대기 중**과 **승인 확정 후** 두 곳 모두에 연결한다
  (한쪽만 연결하지 않는다). 소셜링·클럽 둘 다 CS-05/CS-42에서 대기·참여 두 섹션이
  함께 확인됐기 때문이다.
- 유형별로 실제 캡처가 다른 부분(클럽의 승인제/비승인제 분기, 챌린지의 매일 인증·티타임)은
  그대로 다르게 유지한다 — 강제로 맞추지 않는다.
- **예외: "거절"은 클럽 한정이 아니라 승인제 자체의 일반 메커니즘으로 판단해 소셜링에도
  반영했다.** 특정 호스트의 문구(CS-37)가 아니라 "호스트가 24시간 내 승인/거절/무응답
  중 하나를 고른다"는 구조 자체는 승인제라면 공통일 가능성이 높기 때문이다. 승인 완료
  시점도 "참여 확정"(소셜링)/"가입 완료"(클럽)처럼 별도 상태 노드로 통일했다 — 이전에는
  소셜링만 화살표 라벨로 처리해 노드 자체가 없었다.
- **참가비 유무는 분기(다이아몬드)로 표현한다, 노드 텍스트에 괄호로 덧붙이지 않는다.**
  세 유형 모두 "참가비/활동비 있음?" 결정 → 예: 결제·환불 확인 → 아니오: 다음 단계로
  직행. 유료 클럽 결제 화면 확인, 소셜링 무료 사례(CS-26) 확인으로 세 유형 모두 유료·
  무료가 실제로 갈린다는 근거가 있어 분기 처리가 타당하다.
- "신청 폼"은 별도 단계로 두지 않는다. "예" 선택 후 바로 호스트 질문 답변으로 이어진다
  (CS-18·19가 별도 캡처였지만 같은 화면 흐름으로 병합).
