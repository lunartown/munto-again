# 문토 Current-State Flow

> 상태: Sprint 1.5 작업 전  
> 목적: 리뉴얼 전 문토에서 처음 모임을 고르는 사용자의 실제 흐름을 기록한다.  
> 원칙: 확인한 화면과 추정한 흐름을 구분하며, 개선안은 이 문서에 넣지 않는다.

## 분석 대상

- 사용자: 문토에서 처음 모임을 탐색하는 참여자
- 시작: 모임 목록에 진입
- 종료: 신청·결정 직전 또는 참여 포기
- 보조 상태: 승인·채팅·참석 이후의 후기와 문제 처리
- 확인일: `YYYY-MM-DD`
- 확인 환경: `앱 버전 / 웹 / 로그인 여부 / 지역 설정`

## 현재 플로우

```text
목록 진입 → 검색·필터 → 후보 선택 → 상세 확인 → 신청·결제 → 승인·채팅 → 참석
```

위 흐름은 분석 전 가설이다. 실제 화면을 확인한 뒤 단계·분기·상태를 수정한다.

|---|---|---|---|---|---|---|
| 목록 진입 |  |  |  |  |  | 미확인 |

| 신청·결제 |  |  |  |  |  | 미확인 |

확인 상태는 `확인됨 / 부분 확인 / 가설 / 미확인` 중 하나를 사용한다.

## 플로우 검토 메모

### 사용자가 선택하는 순간

- 어떤 정보가 후보 선택을 유발하는가?
- 후보 간 비교가 가능한가, 각 상세 페이지를 오가야 하는가?
- 참여 결정 전에 확인할 수 없는 정보는 무엇인가?

### 플랫폼이 개입하는 순간

- 정보 입력을 호스트의 자유 서술에만 맡기는가?
- 신청·결제·승인 상태가 명확하게 표시되는가?
- 취소·신고·분쟁 시 책임 주체가 화면에 나타나는가?
