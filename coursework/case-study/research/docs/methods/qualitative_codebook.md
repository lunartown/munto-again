# 정성 데이터 코딩북

## 분석 단위

`불만 글 하나`가 아니라 `하나의 발화 또는 행동 증거 하나`가 카드 한 장이다.
한 문장에 탐색 어려움과 이탈이 함께 있으면 두 카드로 나눈다.

## 1차 태그

| 태그 | 정의 | 포함 예 | 제외 예 |
|---|---|---|---|
| 탐색피로 | 원하는 모임을 찾기 위해 반복 탐색·필터링함 | 여러 페이지를 넘기다 종료 | 단순히 앱이 느림 |
| 숨은만남신호 | 표면상 취미지만 다른 목적이라고 판단함 | 성비, 외모 조건, 로테이션 | 연애 카테고리의 명시적 소개팅 |
| 기대불일치 | 신청 전 기대와 실제 경험이 달랐음 | 활동보다 술·대화 비중이 큼 | 단순 일정 변경 |
| 성비·조건 | 성별 정원, 나이, 외모, 직업 조건에 대한 반응 | 남녀 정원 별도 운영 | 활동 숙련도 조건 |
| 호스트상업화 | 반복 개설, 과도한 판매, 진행 품질 문제 | 같은 상품 대량 등록 | 정상적인 참가비 자체 |
| 안전·신뢰 | 참가자·호스트·정보를 믿기 어려움 | 설명 부족, 신원 우려 | 단순 취향 차이 |
| 경험품질 | 실제 활동·진행·참가자 경험 평가 | 커리큘럼이 좋음/부실함 | 탐색 화면 불편 |
| 이탈행동 | 앱 종료, 삭제, 재방문 중단 | 세 번 실패 후 삭제 | 불만만 있고 행동 없음 |
| 대체서비스 | 다른 채널이나 방식으로 이동 | 오픈카톡, 카페, 인스타 | 다음 문토 모임 탐색 |
| 긍정·반례 | 가설과 반대되는 좋은 경험이나 예외 | 성비 제한이 운영에 도움 | 근거 없는 칭찬 |

## 필드 허용값

- `source_type`: interview / app_review / community / blog
- `sentiment`: positive / neutral / negative / mixed
- `evidence_type`: perception / observed_signal / behavior / outcome
- `evidence_strength`: high / medium / low
- `coding_status`: uncoded / coded / verified
- `pii_removed`: Y / N

## 증거 강도

- high: 구체적인 장면, 신호, 행동, 결과가 연결됨
- medium: 장면 또는 행동 중 하나는 구체적이지만 일부 맥락이 없음
- low: 일반론, 추측, 홍보성 주장, 출처가 불분명함

## 품질 규칙

- 별점만 있고 발화가 없으면 카드로 만들지 않는다.
- 같은 글을 재인용한 페이지는 `dedupe_key`로 묶는다.
- 직접 인용은 필요한 짧은 부분만 저장하고 나머지는 요약한다.
- 검색 결과 요약문만 보고 카드로 코딩하지 않는다. 원문을 열어 확인한다.
- 호스트나 참여자의 이름·연락처·직장 등 개인정보는 저장하지 않는다.
- 가설을 반박하는 카드도 삭제하지 않고 `긍정·반례`로 남긴다.

## 클러스터링 규칙

1. 1차 태그와 무관하게 카드 내용을 다시 읽는다.
2. 비슷한 “상황 → 판단 → 행동”을 묶는다.
3. 클러스터당 최소 3장, 반례가 있으면 함께 기록한다.
4. 클러스터명은 주제가 아니라 관찰된 패턴으로 쓴다.
5. 니즈 문장은 해결책 없이 작성한다.

니즈 문장 형식:

> `[사용자]`는 `[상황]`에서 `[판단/행동을 하기 위해 필요한 것]`이 필요하다.
> 왜냐하면 `[현재 발생하는 비용이나 위험]` 때문이다.
