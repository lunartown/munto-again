# 문토 Current-State Flow — 클럽 중심

> 상태: 범위 수정 중
> 목적: 리뉴얼 전 문토에서 클럽을 처음 고르는 사용자의 실제 흐름을 기록한다.  
> 원칙: 확인한 화면과 추정한 흐름을 구분하며, 개선안은 이 문서에 넣지 않는다.

## 분석 대상

- 사용자: 문토에서 클럽을 처음 또는 초기에 탐색하는 사용자
- 시작: 클럽 목록 또는 클럽 카드에 진입
- 종료: 가입 완료·비가입 결정 또는 탐색 중단
- 보조 상태: 승인·채팅·참석 이후의 후기와 문제 처리
- 확인일: `2026-08-02`
- 확인 환경: iOS 앱 캡처, 로그인 상태 추정. 캡처 파일 기준으로 확인했으며 실제 계정·지역 조건은 후속 기록한다.

## 현재 플로우

```text
클럽 목록 진입 → 검색·필터·정렬 → 클럽 선택 → 상세 확인 → 가입 질문 → 승인 → 가입 완료·채팅
```

이번 개선 범위의 정본은 클럽 흐름이다. 소셜링과 챌린지는 문토의 전체 구조와 클럽 안의
개별 활동 연결을 이해하기 위한 참고 흐름으로 보존한다.

```text
홈·검색·카테고리·찜
  → 클럽 목록·검색 결과
  → 클럽 상세(소개·멤버·활동·댓글)
  → 가입 질문
  → 활동비 확인(있는 경우)
  → 승인제: 가입 대기 / 비승인제: 가입 완료
  → 채팅방·정기 활동 공지
```

## 단계별 기록

| 단계 | 실제 화면명/URL | 사용자가 보는 정보 | 사용자 행동 | 다음 상태 | 이탈·막힘 | 확인 상태 |
|---|---|---|---|---|---|---|
| 클럽 진입 | 홈·클럽 탭·검색·카테고리·찜 | 클럽 카드와 목록을 탐색 | 목록·상세 진입 | 클럽 목록 또는 상세 | 여러 진입점에서 같은 판단 기준이 일관되게 보이는지는 미확인 | 부분 확인 (CS-01, CS-30~31, CS-50) |
| 검색·필터·정렬 | 클럽 검색 결과, 지역·온라인 필터, 정렬 | 조건을 조정해 후보를 좁힘 | 후보 비교 | 클럽 목록 | 활동 주기·최근 활동·활성 멤버 기준으로는 좁힐 수 없음 | 확인됨 (CS-31~35) |
| 후보 선택 | 클럽 카드의 제목·카테고리·멤버 정보 등 | 후보를 선택하거나 찜 | 상세 확인 | 클럽 상세 | 전체 멤버 수만으로 현재 활동성과 실제 참여 규모를 판단하기 어려움 | 부분 확인 (CS-31, CS-50) |
| 상세 확인 | 클럽 소개·멤버·관련 활동·댓글 | 활동 방식과 구성원을 읽고 가입 여부를 판단 | 가입 또는 비가입 | 가입 질문 | 반복 주기·신규 참여 방식·운영 규칙·최근 활동이 공통 기준으로 정리돼 있지 않음 | 확인됨 (CS-36) |
| 가입 질문·활동비 | 호스트 커스텀 질문, 활동비가 있는 경우 결제·환불 정보 | 답변을 작성하고 필요하면 결제 | 가입 대기 또는 완료 | 승인 상태 | 질문은 가입 심사용이며 가입 전 적합성 판단 정보와는 역할이 다름 | 확인됨 (CS-37~38) |
| 승인·가입 완료 | 승인제의 가입 대기, 비승인제의 즉시 가입, 자동 취소 | 상태를 확인하거나 대기를 취소 | 가입 완료 또는 이탈 | 클럽 참여 상태 | 승인 대기 이후 상태는 보이지만 클럽의 지속성과 적합성 판단은 이미 끝난 뒤임 | 확인됨 (CS-39~40) |
| 채팅·정기 활동 | 가입 완료 후 채팅방, 채팅방의 소셜링 탭 | 공지와 활동 일정을 확인 | 반복 활동 참여 | 장기 참여 | 실제 정기 활동 참여·후기·재참여 흐름은 추가 확인 필요 | 부분 확인 (CS-41~42) |

확인 상태는 `확인됨 / 부분 확인 / 가설 / 미확인` 중 하나를 사용한다.

| 반복 주기·진행 방식 | 소개 본문·관련 활동 | 부분적 | 운영자 | 자유 서술과 개별 활동에 분산 |
| 구성원·활성 멤버 | 클럽 멤버 화면 | 낮음 | 플랫폼·운영자 | 전체 멤버와 최근 활동 멤버를 구분하기 어려움 |

| 음주·촬영·연령 조건 | 상세 본문·가입 질문 | 낮음 | 호스트 | 표준 배지·필터 여부 미확인 |

| 활동비·취소 조건 | 유료 클럽의 결제·환불 화면 | 부분적 | 플랫폼 | 무료·유료 클럽이 모두 있어 가입 판단의 공통 핵심 정보는 아님 |
| 문제 발생 시 책임·처리 상태 | 현재 캡처에서 직접 확인하지 않음 | 미확인 | 플랫폼·호스트 | 별도 신고·분쟁 플로우 필요 |

## 플로우 검토 메모

### 사용자가 선택하는 순간

- 어떤 정보가 후보 선택을 유발하는가?
- 후보 간 비교가 가능한가, 각 상세 페이지를 오가야 하는가?
- 참여 결정 전에 확인할 수 없는 정보는 무엇인가?

### 플랫폼이 개입하는 순간

- 정보 입력을 호스트의 자유 서술에만 맡기는가?
- 신청·결제·승인 상태가 명확하게 표시되는가?
- 취소·신고·분쟁 시 책임 주체가 화면에 나타나는가?
