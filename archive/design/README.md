# Design

제품 요구사항을 검증 가능한 사용자 흐름과 구현 가능한 시각 체계로 바꾸는 영역이다.

Sprint 1 전체 과정의 결정·근거·산출물 지도는 [`SPRINT1-MASTER-ARCHIVE.md`](../SPRINT1-MASTER-ARCHIVE.md)를 정본으로 참조한다.

전체 폴더 구조와 저장 규칙은 [`PROJECT-INDEX.md`](../PROJECT-INDEX.md)를 함께 참조한다.

## 구조

- `flows/`: 사용자 여정, 태스크 플로, 상태와 예외
- `prototypes/`: 컨셉·사용성 검증용 프로토타입 설명과 링크
- `system/`: 토큰, 컴포넌트, 접근성, 콘텐츠 규칙
- `assets/`: 코드와 문서에서 사용하는 최적화된 시각 자산

## 정본 규칙

- 원본 화면 디자인은 Figma를 정본으로 사용하고 파일·페이지·노드 링크를 문서에 기록한다.
- 이 저장소에는 결정 이유, 흐름, 상태 명세와 구현용 자산을 남긴다.
- PNG/PDF 내보내기를 무분별하게 쌓지 않고, 실제 전달·검증에 사용하는 버전만 보존한다.
- 컴포넌트가 코드로 구현되면 `development/packages/ui`의 Storybook 또는 동등한
  카탈로그와 연결한다.

## 디자인 완료 조건

- 정상 흐름뿐 아니라 빈 상태, 오류, 로딩, 권한과 위험 상태가 정의됨
- 키보드·스크린리더·명도 대비 등 접근성 요구가 기록됨
- 제품 요구사항과 성공지표에 연결됨
- 디자인 토큰과 공용 컴포넌트 사용 여부가 결정됨
- 구현자가 추측해야 하는 정책이 남아 있지 않음
